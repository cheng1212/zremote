## 三、发现项

### A1 · 需修复：Web 端 CAS 集合与 Dart 端存在疑似漂移
- 扫描 diff 显示 `web/src/protocol/constants.ts` 的 `CAS_COMMANDS` 附近 `applyFileRewind` 出现两次（Dart 端一份）。疑似 grep 窗口扫到了紧邻的 `ROW_TARGET_COMMANDS`，**未确认真重复**；但 TS 端 CAS/ROW_TARGET 两个集合没有任何一致性测试锁住，漂移风险真实存在（CAS 漏一个 = 该命令并发时静默丢乐观锁）。
- **建议**：写一个 Node 单测，直接 `import` 两侧集合做 deepEqual（TS 侧 import；Dart 侧生成 JSON 快照入库供其比对）。10 分钟工作量，永久防漂移。

### B1 · 建议：Timer 盘点表
- app_controller 有 20 处 Timer 相关代码（token ticker、全局轮询、相位释放、slow timer 等），dispose 路径已覆盖主要几个，但**没有一个集中的"存活 Timer 清单"**。建议在 dispose 里统一 `Timer?` 字段全量 cancel（机械劳动，防泄漏）。

### B2 · 建议：常驻集合容量上限
- app_controller 18 个内存集合（相位覆盖/去重账/标题缓存等）多数有清理路径，但 `_recentNotified`（90s 去重账）之外的部分如 `_notifiedTitles`、`_taskTokens` 无上限。单用户单机场景量级无害；若未来多 workspace 大列表，建议统一加 LRU 或容量上限。

### B3 · 建议：`flutter test` 代理坑流程化
- 本机 WorkBuddy 注入代理会让 flutter_tester 全线假失败（HANDOVER-Z 已记）。建议写进 `Makefile`/脚本（`test.sh` 自动带 no_proxy），新 agent 不再踩。

### B4 · 建议：Web 端协议测试为零
- web/ 目前 0 测试。crc32/valueCodec/rpcFrames 是纯逻辑，最易单测且最值得（协议正确性的底线）。建议下一班补 `vitest` 三件套。
