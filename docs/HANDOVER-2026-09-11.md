### BUG-12 要点（最新一条，最可能需要接着验）
- 根因：`lib/main.dart` 把整个 App 的根 widget 由连接状态推导
  （`workspace != null || workspaces.isNotEmpty ? HomeShell : PairPage`），
  而 `connect()` 开头就 `disconnect(silent: true)` 清空工作区 → 重连全程停在 `PairPage`。
- 方案：`ZApp` 收敛出 `showMainShell`（根 widget 判定）与 `isReadOnlySnapshot`（UI 判定）；
  `disconnect({keepShell})` / `connect({keepShell})` 支持"只拆连接、保留列表"；
  新增 `openPairPage()` + 抽屉「去连接 / 换链接」入口；会话页加就地提示条
  （重连中 / 已断开），只读快照期卡片点击给明确提示、FAB 隐藏。
- 用户拍板的两条（经 `AskUserQuestion`）：
  1. 断开后**留在会话页**，列表只读，顶部提示，抽屉补「去连接」入口；
  2. 重连期间**保留旧列表**，顶部提示「重连中…」，连上后自动刷新。

## 5. 本次会话的坑（已入 `docs/LESSONS.md`，摘要）

- **同一文件绝不并发 Edit**：一次消息里发多个 Edit 到同一文件会互相覆盖，只有最后一个生效。
  改同一文件必须串行，改完用 `git diff` 复核。
- **收尾动作不能放在用户可感知的关键路径上等满超时**（BUG-10）：
  `ChannelClient.call` 默认 30s，退订没覆盖 → 拆栈串行等满 60s。
  另外**fail-fast 的位置很重要**：做 fail-fast 的调用排在需要 fail-fast 的等待之后，等于没做。
- **后台流量和用户操作共享队列时，"多发一点"就是"让用户多等一点"**（BUG-11）。
- **判"卡顿"要用"排空暴发"判据**（多个不相关调用耗时**完全相同**且同刻完成），
  不能用"静默时长"——`off-peak-task.list` 每 60s 一跳，空闲时段天然有大段静默。
- **判"已断开"不能用 `session == null`**（BUG-12）：语义是"还没连过"，会误伤裸 `ZApp`
  的 widget 回归锁；且重连失败后 `session` 对象仍在，会露出"假活"态。
- **日志里的"成对相同调用"多半是日志重复写入**（host 进程写一次、主进程转发再写一次，
  相隔 20~40ms，耗时差≈时间差）——别当重复订阅去报 bug。
