# zremote 已知局限与可选增强清单

> 来源：2026-09-11~12 全量扫描（见 docs/SCAN-MATRIX.md）。每条都经过代码层确认。
> 定位：**不是 bug 清单**（bug 见 BUGFIXES.md）——是"知道但有意不做/做不到/低价值"的边界记录。

## A. 已知局限（有意接受，附原因）

1. **滚动锚定的"位置盲补偿"**：像素增量法分不清高度变化发生在哪条消息——旧消息里
   的图片加载会把历史区撑高，被误当流式增长补偿，视口多移一段。业界同款局限
   （flyerchat 用消息尺寸控制器解决）。改进路径=内容锚定（按消息 id 记锚点），
   改造风险 > 当前收益，不动。
2. **附件整文件读进内存**：>100MB 在选择时拦截。分片读取可解，但 file_picker 的
   bytes 模式限制如此，改造收益低。
3. **图片缓存进程内 64MB LRU**：冷启动后首屏重新拉取。持久化缓存可做但增加
   存储管理复杂度，等真实痛点。
4. **配对凭据明文存 SharedPreferences**：自用可接受；对外分发前必须迁移
   flutter_secure_storage + 处理 applicationId/签名/混淆（README 已记录）。
5. **多设备同时切同一会话的模型**：以服务端最后一次写入为准（对账逻辑已闭环，
   不会打回）。同一会话别两台设备同时开着切即可。

## B. 可选增强（用户提了再做）——⏳待裁决+UI 对照新增

UI-A. **新消息入场动画** ✅ 已落地（_RowEntrance 渐显+微上滑 180ms，按 rowId 一次）。

## C. 不可达/需桌面端配合（客户端无法解决）

1. **workspace/setDefaultModel 族**（服务端工作区默认模型=跨设备默认的正解）：
   未挂移动端 Channel IPC 路由（源码+探针双证）。关注桌面端更新。
2. **registryFallback 夜间刷模型**：桌面端机制，客户端护栏（批量对账+守恒器）已能
   自动纠正；根治需桌面端改。
3. **session/setModel 的 persistAsWorkspaceLastUsed**：runtimeModel 参数需要 host
   内部指纹（revision/generatedAt），移动端不可自拼。
4. **setTaskUnread**：桌面端 3.11.2 无此方法（源码无 zod 定义）+ 客户端无未读 UI 面。

## D. 值得关注的观察（非问题）

1. 桌面端「同步当前模型 runtime config」机制一天 1056 次——它是模型拉锯的推手，
   客户端守恒器已能对抗；若未来发现新的模型漂移，先查它。
2. tasks-index.sqlite 是排查服务端行为的金矿（tasks/automations/automation_runs
   表，含 deleted/archived/title_overridden 标记）。
3. 桌面日志 `~/.zcode/v2/logs/YYYY-MM-DD.log` 含全部 RPC 调用记录（zcode-host
   [rpc:call] 行），grep 前记得加 -a（含二进制字符）。
