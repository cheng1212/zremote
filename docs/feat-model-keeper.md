# 变更说明：模型守恒器（不切就是英伟达，切了就按实际模型）

> 提交：`83b53f6`（develop）　日期：2026-09-06
> 前置：《zremote-桌面端交互深度研究报告.md》+ 两轮探针实测

## 需求（用户原话）

「第一次会话我不切就是英伟达的模型，我切了就按照实际模型」

- 新会话不手动选模型 → 稳定在 nv-nemotron-ultra（本地 4002 代理），不许被桌面端悄悄改走
- 手动切了（模型面板选了 X）→ 会话按 X 走，同样不许被改走

## 实测背景（为什么 5 次上限的守卫不够）

1. 桌面端 host 服务有高频"同步当前模型 runtime config 到 ZCode agent"机制（今日日志 825 条，活跃会话每 10~35 秒一次），把桌面当前模型（GLM-5.3-Flash）推给会话运行时。
2. 两轮探针实测（`test/manual_model_watch_test.dart`）：新建 nv 会话空置 150s、发消息跑完回合再观 180s，**可见 config 均 0 翻转**——同步标着 `applyModelSelection:false`，多数时候不改可见模型；但用户真机上确实观察到"自己回去了"，对应桌面端特定时机（聚焦写入/运行时重挂载）的写入。
3. 旧守卫 `_guardSessionModel` 限流 3s/5 次且**每次进页面计数清零**——桌面端反复写入超过 5 次后守卫永久失活，模型留在被改走的状态。这正是"自己回去了"的直接机制。

## 实现

1. **守恒器 `_keepSessionModel`**（替换 `_guardSessionModel`）：
   - **去掉 5 次上限**：会话意图模型长期成立，漂移就纠正；
   - **退避节奏**：5s 起步，连续纠正翻倍封顶 60s，发现对齐即复位——真拉锯时收敛到每分钟一次，不刷屏不空转；
   - **运行中不换马**：`isRunning` 或有流式行时跳过，回 idle 再补纠正；
   - 对齐判定复用 `_assertLocalModel` 同源逻辑（provider 词形容错）。
2. **意图模型登记**：新会话闸门（模型就绪验证）通过后，立即 `recordSessionModel(chosen:true)` 登记 nv 为意图模型；用户在模型面板改选走 `_applyModel` 的既有记录。守恒器保护的就是这条记录——"不切=英伟达、切了=实际模型"统一由它承载。
3. 无记录的老会话仍不守恒（`shouldApplyPreferredDefaultModel` 为 true 时跳过），行为与此前一致。

## 验证

- `flutter analyze` 0 问题；`flutter test` 69 全过
- 探针工具入库：`test/manual_model_watch_test.dart`（建会话→发消息→监视 180s 模型翻转时间线，结束自删会话）、`test/manual_cleanup_test.dart`（清理残留）。均环境变量门控，无凭证自动 skip。

## 边界说明

- 用户在**桌面端**切换某会话模型时，若手机端该会话页正开着，守恒器会按手机记录纠正回去（单人使用以手机为准；文档明示）。桌面端的切换在没有手机页监视时不受影响。
- 意图模型依赖本地记录（SharedPreferences），换设备/清数据后首次打开会话由 reconcile 重建为 nv 默认。
